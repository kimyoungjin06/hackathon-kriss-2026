목표

참가자는 3시간 동안 다음 과정을 한 번 완주합니다.

  1. 반복되는 업무를 작은 입력과 출력으로 정의합니다.
  2. 생성형 AI와 코드 도구를 이용해 작동하는 첫 버전을 만듭니다.
  3. 수치, 인용과 해석을 사람이 다시 검증합니다.
  4. 실행 방법과 남은 한계를 짧게 기록합니다.

완성품 제작보다 작동 범위와 실패 조건을 확인하는 것이 목표입니다.

1부 · AI에게 일을 맡기는 기준 (0:00–0:10)

  • 정확하고 반복 가능한 계산은 코드와 전문 라이브러리에 맡깁니다.
  • 요약, 분류 후보와 문장 초안은 LLM에 맡길 수 있습니다.
  • 후보 생성과 최종 판정을 분리합니다.
  • 외부 상태를 바꾸는 작업은 권한과 검토 단계를 둡니다.

핵심 원칙은 세 가지입니다.

  1. 입력과 원하는 출력의 예시를 함께 제공합니다.
  2. 작은 기능부터 만들고 결과를 보며 반복합니다.
  3. AI의 답도 검증 대상이라고 가정합니다.

2부 · 라이브 데모 (0:10–0:18)

반복 측정값을 입력하면 평균, 표준편차와 A형 불확도를 계산하고 보고서 문장을 만드는 작은 웹 도구를 제작합니다. 첫 결과의 문제를 확인하고, 예시와 검증 조건을 추가해 개선하는 과정을 보여줍니다.

3부 · 사례와 쇼케이스 (0:18–0:27)

화학·재료 분야 해커톤 사례를 다음 여섯 유형으로 살펴봅니다.

  1. 원클릭 분석 파이프라인
  2. 문서·데이터 질의 인터페이스
  3. 자율 에이전트 워크플로
  4. 모듈과 연구 인프라
  5. 벤치마크와 평가
  6. 모델 조정과 로컬 배포

CiteSage 쇼케이스에서는 문헌 테마, 인용 기반 답변, 시기 간 연결과 연구 흐름을 살펴봅니다. 화면의 OpenAlex ID와 출처 카드는 문헌 식별과 검토를 돕지만, 시각화 자체가 과학적 결론을 대신하지 않습니다.

4부 · 실습 규칙 (0:27–0:30)

트랙

  • 트랙 A: 단일 페이지 업무 도우미
  • 트랙 B: 공개 측정 데이터 분석 도구
  • 트랙 C: 공개 문헌·DB를 사용하는 리서치 워크플로

데이터 신호등

등급 예 행동
GREEN 공개 자료, 교육용·합성 데이터 사용 가능
YELLOW 내부 구조를 반영한 데이터 공개 샘플이나 합성 데이터로 대체
RED 개인정보, 인증정보, 계약·보안 정보 외부 AI 입력 금지

해킹과 발표 (0:30–3:00)

시간 활동
0:30–0:40 팀별 과제 선택과 한 줄 목표 작성
0:40–2:20 구현, 검증, 실행 기록 작성
2:20–2:34 12팀 × 1분 1차 발표
2:34–2:38 현장 투표와 상위 4팀 선정
2:38–2:55 상위 4팀 × 4분 최종 발표
2:55–3:00 최종 투표와 마무리

각 팀은 작동 데모, 프롬프트 또는 작업 기록, 다섯 줄 이상의 재현 메모를 남깁니다.
