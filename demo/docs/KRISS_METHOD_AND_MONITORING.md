# KRISS 문헌 수집·검증 방법과 품질 모니터링

> 대상: CiteSage KRISS 화학 문헌 예시(`kriss-chem`)  
> 최초 기록: 2026-08-12  
> 현재 상태: `SOURCE_IDENTITY=FAIL` · `CLEAN_DATA_REBUILD=NOT_RUN` · `PUBLIC_RENDER=PASS`

이 문서는 KRISS 화면에 표시된 결과만 설명하지 않는다. 어떤 문헌을 왜 수집했는지, 어떤
변환을 거쳤는지, 어디서 오류가 생길 수 있는지, 무엇을 측정해야 공개 가능한지를 함께 기록한다.
목표는 오류가 없다고 선언하는 것이 아니라 **오류가 드러나고 다음 빌드를 막을 수 있는 구조**를
만드는 것이다.

## 1. 현재 범위와 주장 단위

현재 스냅샷은 OpenAlex에서 수집한 제목·초록 기반 분석 문헌 집합이다. 아래에서는 이 집합을
간단히 코퍼스라고 부른다.

| 소스 세트 | OpenAlex 필터 | 현재 스냅샷 |
|---|---|---:|
| KRISS 시드 | `authorships.institutions.lineage:I2799611809`, 초록 있음 | 7,970 |
| Metrologia | `primary_location.source.id:S7291761`, 초록 있음 | 5,931 |
| Accreditation and Quality Assurance | `primary_location.source.id:S177975795`, 초록 있음 | 116 |
| 분석화학 배경 | topic `T10908`, 2000년 이후, 피인용 100 초과 | 4,396 |
| 측정불확도 배경 | topic `T11890`, 2000년 이후, 피인용 100 초과 | 439 |
| 중복 제거 후 합계 | 첫 수집 세트 우선 | 18,852 |

이 수치는 **교정 전 관측 스냅샷**이다. 2026-08-12 확인된 source identity 오류 때문에
검증 완료 코퍼스 크기로 인용하면 안 된다. 코퍼스 전체를 새로 정제한 뒤 숫자를 다시 확정한다.

현재 인스턴스가 주장하지 않는 것:

- KRISS 기관 전체 연구의 완전한 목록
- 화학소재측정본부 소속만의 폐쇄된 코퍼스
- PDF 본문 전체를 검색한 결과
- 인용 연결로 입증한 과학적 계승·영향·인과
- KRISS 측정·화학 분야 전문가가 승인한 최종 해석

## 2. 현재 데이터 처리 방법

수집기는 다섯 소스 세트를 위 순서대로 요청하고 OpenAlex work ID로 중복을 제거한다. 현재
저장 레코드는 제목, 연도, DOI, venue 표시명, 저자, topic, 복원한 초록, 참고문헌 ID,
OA 상태와 `source_set`을 보존한다.

현재 구현에는 두 가지 중요한 한계가 있다.

1. **기존 파일을 읽어 그대로 보존하는 증분 수집**이다. 필터를 고쳐 다시 실행해도 이미 들어온
   오류 레코드는 제거되지 않는다. 따라서 정제 빌드는 기존 파일 위 재실행이 아니라 별도 경로의
   fresh build여야 한다.
2. `primary_location`의 source ID·ISSN·권호 등 source identity 핵심 필드를 최종 JSONL에
   충분히 보존하지 않는다. venue 표시명만으로는 이름 충돌이나 잘못된 소스 연결을 사후 감사하기
   어렵다.

검색은 의미 기반 검색(bge-m3), 키워드 검색(BM25), 결과 재정렬과 인용 그래프를 사용한다. 현재 공개 예시는
PDF·청크 인덱스를 구축하지 않았으므로 제목·초록 범위에서 자동 강등해 작동한다. 시각화는 같은
코퍼스와 인용 ID를 사용하지만, 군집 라벨·분야·설명은 대표 논문을 입력으로 LLM이 생성한 탐색용
분류다.

### 2.1 시기별 주제와 인용 화면의 표시 계층

시기별 주제 화면의 기본 군집 98개와 더 세분한 군집 148개는 서로 다른 Leiden 해상도에서 만든
별도 분류다. 기본 화면에서 98개를 모두 동시에 그리면 시기별 군집이 17–25개가 되고 라벨 대부분이
보이지 않았다. 따라서 군집 결과를 삭제하거나 `기타`로 합치지 않고 다음 탐색용 상위 계층을 추가했다.

- 각 시기 군집의 대표 논문 임베딩 평균을 계산한다.
- 기본 군집의 논문 수를 가중치로 사용해 k-means 7개 상위 주제군을 만든다
  (`random_state=42`, `n_init=20`).
- 검토한 기준 군집으로 상위 주제 이름을 고정하고, 모든 하위 군집이 정확히 한 상위 주제군에
  들어가는지 검사한다.
- 출처 오류로 확인된 교통 문헌은 숨기지 않고 `출처 오류 교통 문헌`으로 분리한다.
- 기본 98개와 세분 148개의 시기별 논문 합계, 기존 표시용 군집 연결의 인용 합계를 각각 보존한다.

이 7개 상위 주제군은 화면 탐색용 계층이며 과학적으로 검증된 분류가 아니다. 현재 연결선도 기본
군집 생성 단계에서 선별해 보존한 195개 인접 시기 연결을 합친 값이므로 전체 직접 인용을 뜻하지
않는다. clean rebuild 뒤 기준 군집과 상위 명칭을 다시 검토해야 한다.

기본 화면의 열은 실제 관측 연도 `1933–2004`, `2005–2009`, `2010–2014`, `2015–2019`,
`2020–2026`이다. 각 블록은 `해당 주제 논문 수 / 그 시기 전체 논문 수`와 구성비를 함께 표시하고,
하단 막대도 같은 시기 내 구성비를 0–100% 선형 길이로 나타낸다. 첫 구간은 72년이고 나머지 구간은
5–7년이므로 절대 논문 수나 구성비만으로 시기 사이의 연구량 증가·감소를 판정하지 않는다. 인용선은
최초 화면에서 숨긴다. 블록을 선택하면 그 `시기×주제` 블록에 직접 닿은 인접 시기 경로만 남기고,
상위 주제 버튼은 해당 주제의 가장 이른 관측 블록을 선택한다. 선택 패널은 앞 시기에서 온 연결과
뒤 시기가 해당 선행 주제를 인용한 연결을 분리하며, 각 방향의 표시용 직접 인용 합계를 100%로 둔
정렬 막대와 정확한 건수를 함께 제공한다. 이 비율의 분모는 전체 인용이 아니라 기존 기본 군집
데이터가 보존한 표시용 인접 시기 연결이다.

선행 시기 인용 구성 화면은 인용 분모를 섞지 않는다. 기본 막대의 행별 분모는 해당 후속 시기의
정확한 연도 순서가 정상인 문헌 집합 내부 시기 간 직접 인용이며 각 행은 100%가 된다. 원시
10개 시기쌍 24,377건, 같은 시기·과거 연도 14,779건, 같은 연도 2,596건, 문헌 집합 밖
498,612건을 별도로 보존한다. 미래 연도 관계는 같은 시기 126건과 뒤 시기 139건을 합친
265건이며 연도 누락은 0건이다. 관측한 참고문헌 연결 540,629건 가운데 정확한 연도 순서가
정상인 문헌 집합 내부 인용은 41,752건(7.723%)이다. 시기 구간 관계와 정확한 연도 관계는
서로 대체하지 않으며 두 값을 각각 검사한다.
원시 흐름도는 보조 상세 화면에서만 제공하며 막대 높이와 리본 폭을 모두 시기 간 인용 건수로
통일한다.

## 3. 확인된 source identity 사고

테마 지도의 「대중교통 시스템 개선」 군집은 478편이며 KRISS 시드 문헌은 4편(0.84%)이다.
대표 논문 8편은 수집 데이터에서 모두 `metrologia` 세트로 태깅됐다.

대표 사례 `W591077760`을 대조하면:

| 항목 | OpenAlex 레코드 | 외부 서지 대조 |
|---|---|---|
| 제목 | BUS RAPID TRANSIT, BY ANY OTHER NAME | 동일 |
| source | Metrologia | Metro |
| ISSN | 0026-1394 | 10098-0083 |
| 권호 | 99(2) | 99(2) |
| 분야 | Transportation Planning and Optimization | 대중교통/BRT |

OpenAlex의 source ID 필터는 요청한 대로 작동했지만, 개별 work가 잘못된 source에 연결돼 있었다.
그 결과는 다음과 같이 전파됐다.

`잘못된 source identity` → `측정학 배경 코퍼스 편입` → `교통 문헌끼리 정상 군집화`
→ `LLM이 군집을 정상적으로 설명` → `그럴듯한 잘못된 KRISS 지도`

이는 클러스터링 실패나 LLM 환각만으로 설명할 수 없다. 방법론의 첫 관문인 source identity
검증이 없었던 데이터 계보 문제다. `기타 제외` 토글로 군집을 숨기는 것은 교정이 아니다.

확인 자료:

- OpenAlex work API: <https://api.openalex.org/works/W591077760>
- OpenAlex source API: <https://api.openalex.org/sources/S7291761>
- TRID 서지 레코드: <https://trid.trb.org/View/644532>

## 4. 검증 상태 모델

모든 단계는 독립적으로 판정한다. 앞 단계의 `PASS`가 다음 단계를 대신하지 않는다.

| 상태 | 의미 |
|---|---|
| `PASS` | 정의된 검사와 증거가 모두 충족됨 |
| `WARN` | 결과는 생성할 수 있지만 사람이 확인해야 하는 이상 신호가 있음 |
| `PENDING` | 필요한 검토가 진행 중이며 공개 판정에 사용할 수 없음 |
| `FAIL` | 알려진 오류가 있어 후속 빌드·공개를 중단해야 함 |
| `NOT_RUN` | 검사를 수행하지 않음. `PASS`로 해석하면 안 됨 |

검증 계층:

| 계층 | 질문 | 현재 상태 |
|---|---|---|
| `SOURCE_DEFINITION` | 선택한 기관·저널·topic ID가 의도한 대상을 가리키는가 | `WARN` |
| `SOURCE_IDENTITY` | 개별 work의 source ID·ISSN·권호·DOI가 실제 출처와 일치하는가 | `FAIL` |
| `CORPUS_COMPOSITION` | 소스 세트·분야·연도·기관 구성에 설명되지 않은 이상치가 없는가 | `PENDING` |
| `INDEX_LINEAGE` | 인덱스가 승인된 코퍼스 스냅샷에서 만들어졌는가 | `PENDING` |
| `ARTIFACT_LINEAGE` | 7개 공개 화면이 같은 승인 스냅샷·기간·질의를 사용하는가 | `PENDING` |
| `PUBLIC_RENDER` | 추적 JSON만으로 공개 HTML 7개를 원 코퍼스 없이 동일하게 다시 그릴 수 있는가 | `PASS` |
| `CITATION_ID` | 답변의 모든 W ID가 승인 코퍼스에 존재하는가 | 공개 3건 `PASS` |
| `SOURCE_SUPPORT_REVIEW` | 인용 초록이 해당 답변 문장을 지지하는가 | 3건 `PASS`, 5건 `FAIL/PENDING` |
| `DOMAIN_EXPERT_REVIEW` | 측정·화학 전문가가 내용과 범위를 검토했는가 | `NOT_RUN` |
| `PUBLICATION_PARITY` | KRISS용 여섯 시각화와 상태 문서가 CiteSage Pages에 배포됐는가 | `FAIL` |

## 5. 빌드마다 모니터링할 지표

### 수집·식별

- 소스 세트별 전체·신규·제외 레코드 수와 전 빌드 대비 변화
- work ID, source ID, ISSN-L, ISSN, DOI, venue, 권·호·연도의 보존율
- source ID와 외부 식별자(ISSN/DOI)가 충돌하는 레코드 수
- DOI가 없고 단일 레거시 ID만 있는 레코드의 수와 비율
- 한 work가 여러 소스 세트에 걸린 경우 최초 우선순위와 중복 제거 근거

### 구성·이상치

- 소스 세트별 OpenAlex topic·연도·문헌 유형 분포와 이전 빌드 대비 변화
- 각 micro-cluster의 소스 세트 구성, KRISS 수·비중, 대표 논문 ID
- 기관·저널의 기대 범위와 충돌하는 고립 군집 및 상위 대표 논문
- LLM이 `기타`로 분류한 군집과 분류 실패를 구분한 수치

topic 문자열만으로 자동 삭제하지 않는다. 예를 들어 `electron transport`는 측정학·물리 문헌에서도
정상적으로 나타난다. 이상 신호는 후보를 만들고, 삭제는 source identity와 서지 근거로 결정한다.

### 결과·배포

- 코퍼스 매니페스트 SHA와 dense/BM25/graph 인덱스 입력 SHA
- artifact에 내장된 논문 수·논문 ID·질의·기간과 승인 매니페스트의 일치
- SciSci와 KRISS의 공개 탭 수 및 각 링크의 HTTP/브라우저 실행 상태
- 답변별 `CITATION_ID`, `SOURCE_SUPPORT_REVIEW`, `DOMAIN_EXPERT_REVIEW`
- 선행 시기 인용 구성 화면의 시기 간·같은 시기·문헌 집합 밖·미래 연도·연도 누락 계수와 각 분모

## 6. 교정·재빌드 절차

여기서 두 재빌드를 구분한다.

- **public render**: Git에 추적된 검토 JSON에서 공개 HTML 7개를 다시 그린다.
  `make build-public-artifacts`가 담당하며 clean checkout에서 원 코퍼스 없이 실행된다.
- **clean data rebuild**: OpenAlex 수집부터 코퍼스·인덱스·군집·검토 JSON을 별도 스냅샷으로
  다시 만든다. 아래 절차가 해당하며 현재 `NOT_RUN`이다.

1. 기존 18,852편 파일을 읽어 누적하지 않고 별도 경로에 fresh corpus를 만든다.
2. source ID·ISSN·권호·DOI·OpenAlex 갱신일을 손실 없이 저장한다.
3. 소스 세트별 identity·구성 보고서를 만들고 이전 스냅샷과 차이를 기록한다.
4. 이상 군집과 대표 논문을 사람이 검토하며 제외 ID와 근거를 보존한다.
5. `SOURCE_IDENTITY=PASS`와 `CORPUS_COMPOSITION=PASS` 전에는 인덱스와 공개 아티팩트를
   승격하지 않는다.
6. 승인 코퍼스에서 의미·키워드·인용 그래프 인덱스와 테마 지도, 시기별 상위 주제·세부 군집,
   선행 시기 인용 구성과 원시 흐름, 논문 인용 흐름, 타임라인, 논문별 근거 검토를 모두 다시 만든다.
7. 공개 답변을 다시 검색·생성하고 인용 ID·초록 지지 범위를 재검토한다.
8. README와 모든 화면의 논문 수·분모·검증 상태를 새 매니페스트에서 생성한다.
9. `main/docs/kriss`를 재조립해 GitHub Pages에서 여섯 시각화와 검토 답변을 브라우저로 확인한다.

## 7. 공개·릴리스 규칙

- `SOURCE_IDENTITY` 또는 `CORPUS_COMPOSITION`에 `FAIL`이 하나라도 있으면 코퍼스 전체를
  대표하는 수치·지도·분야 비교를 공개 결론으로 승격하지 않는다.
- `PENDING`과 `NOT_RUN`은 완료가 아니며 상태를 그대로 노출한다.
- 오류 레코드와 제외 근거를 삭제하지 않고 버전별 audit artifact로 보존한다.
- 지도에서 보이지 않게 하는 UI 필터는 데이터 제외나 검증을 대신하지 않는다.
- 정적 HTML이 정상 렌더돼도 데이터·인덱스·서사의 계보가 맞지 않으면 릴리스하지 않는다.
- 공개본에는 방법론 문서, 현재 상태, 알려진 문제, 마지막 확인일을 함께 연결한다.
- 행사 export manifest는 정본 Git SHA, 정본 worktree 상태, 각 HTML 빌더와 추적 입력 JSON의
  SHA-256을 보존한다. `DIRTY` export는 내부 미리보기에만 허용하고 공개 릴리스 CI는 거부한다.

## 8. 현재 공개 해석

현재 KRISS 시각화는 **수집·분석 절차와 화면 구성을 확인하는 출처 정제 전 예시**로만 취급한다. 18,852편과
그로부터 계산한 군집·분야·인용 집계는 fresh clean rebuild가 끝날 때까지 확정 수치가 아니다.
공개 답변 3건의 초록 지지 검토는 별도 범위에서 유효하지만, 코퍼스 전체 source identity와
측정·화학 전문가 검토를 대신하지 않는다.
