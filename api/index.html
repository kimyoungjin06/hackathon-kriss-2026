공개 초안 · 행사에서 사용할 API의 최종 주소와 접근 방식은 확정 후 이 문서에 반영합니다.

이 문서는 참가자가 공개·합성 데이터를 이용해 API 기반 실습을 시작할 때 필요한 공통 원칙을 설명합니다. 실제 인증정보나 비공개 엔드포인트는 저장소에 기록하지 않습니다.

현재 공개 범위

  • API를 사용하는 과제의 입력과 출력 구조
  • 공개 가능한 요청·응답 예시
  • 오류가 발생했을 때 확인할 항목
  • 사용량과 요청 빈도에 관한 공개 기준
  • 데이터 안전과 인증정보 보관 원칙

최종 API가 정해지면 기본 URL, 인증 방식, 최소 실행 예시와 오류 코드를 추가합니다.

안전 원칙

  1. 공개 자료와 교육용·합성 데이터만 전송합니다.
  2. API 키나 토큰을 코드, 노트북, 화면 캡처 또는 Git 커밋에 남기지 않습니다.
  3. 인증정보는 환경변수나 행사에서 지정한 보안 저장소로 전달합니다.
  4. 요청 전에 입력에 개인정보, 계약·보안 정보가 없는지 확인합니다.
  5. 수치와 인용이 포함된 응답은 원자료나 별도 코드로 다시 검증합니다.

공개 예시 형식

최종 안내에는 다음과 같은 최소 예시가 들어갑니다. 아래 값은 문서 구조를 보여주기 위한 자리표시자이며 실행되지 않습니다.

curl "$API_BASE_URL/example" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"공개 예시 질문"}'
{
  "answer": "예시 응답",
  "sources": [],
  "status": "example"
}

오류 확인 순서

  1. 기본 URL과 경로가 최신 안내와 일치하는지 확인합니다.
  2. 인증정보가 코드에 직접 적히지 않고 실행 환경에 설정됐는지 확인합니다.
  3. 요청 본문의 필드명과 JSON 형식이 예시와 일치하는지 확인합니다.
  4. 같은 요청을 작은 공개 예시로 다시 실행합니다.
  5. 반복 실패하면 인증정보를 공유하지 말고 오류 코드와 요청 구조만 전달합니다.
